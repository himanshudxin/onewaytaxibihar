# GSD Execution Rules

1. **Structured Discipline**: Always establish a plan or roadmap before touching code in multi-file features.
2. **Atomic Edits**: Never rewrite entire files if a targeted replacement or multi-replace suffices.
3. **Continuous Verification**: After code changes, verify runtime syntax, build steps, and tests before concluding.
4. **Context Hygiene**: Keep messages and context focused; record decisions and state in project markdown files (`PRD.md`, `progress.txt`).
